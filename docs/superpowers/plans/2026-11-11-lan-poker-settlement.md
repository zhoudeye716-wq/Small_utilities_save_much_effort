# 线下围坐局域网联机与盈亏查看 Implementation Plan

> 实施时使用 Superpowers 的执行计划流程，逐项测试；本文件只是计划，不代表功能已经实现。

**目标：** 保留现有单机围坐，增加局域网多人牌桌，并为两种模式提供不改变牌局的盈亏和转账建议。

**架构：** 局域网以房主为唯一牌局确认方；玩家发送带唯一编号的操作，房主校验、持久化后递增版本并同步快照。玩家的视角变换只影响显示，不改变真实座次和牌桌规则。单机与联机共用牌局和盈亏计算，但使用各自的存储键。

**技术：** 微信小程序和 Android 共用 JavaScript、WXML、WXSS；局域网使用 UDP 和本机存储；自动测试使用 Node.js 内置测试运行器。

**设计依据：** 本会话中用户确认的房间、座位、身份、断线、恢复和盈亏需求，以下「确定的行为」为具体执行依据。

## 全局约束

- 保留本地牌桌的玩法、座位朝向、赢家及平局结算；只新增盈亏查看入口和新局记录。旧版缺少补筹码记录的牌局不做迁移或补录，不得用猜测数据生成可靠盈亏。
- 微信小程序和 Android App 复用源码，分别处理平台差异；不构建安装包，由用户自行构建。局域网不依赖云服务器。
- 房间不用预先设置人数，实际在桌 2–9 人，含房主；先后加入的总人数可超过 9 人。玩家与座位分离，等待或离场的历史玩家不可被删除出本场盈亏。
- 每人设备显示自己的座位在下方，所有文字对当前设备正向；桌面其他位置按真实座次排列，不能改变庄家、盲注和行动次序。
- 保持主池、边池、全下、未被跟注退款、平局余数等现有规则。使用整分金额计算，最低单价 0.01 元；对超过两位小数的输入不得静默截断，须通过精确计算或明确提示。
- 每台设备只保留最近的联机房间数据；新房间确定建立或加入后才覆盖旧记录。单机数据与联机数据隔离。昵称与房间名只保留各自最近一次的本地值；正常覆盖安装更新保留数据的前提是系统保留应用数据、包名和签名不变。
- 未经用户再次要求，不执行 Git 提交、推送或安装包构建。

## 确定的行为

1. 现有设置页新增联机入口。房主创建时填写房间名、昵称、盲注、初始筹码、单价；密码默认关闭，可由房主启用。房间列表搜索后输入昵称、选座，密码房间加入时输入密码。房主等至少两人在座且准备合适后主动开始。
2. 玩家每人独立操作自己的座位，只能在自己行动时下注、跟注和弃牌；房主负责选庄、补筹码、各底池赢家与平局选择。保留现有分池结算与自动胜出规则。局域网模式不提供重置牌桌。
3. 新玩家在小局进行时加入等待区，小局结算后再进入牌桌。等待区满员的原玩家保留其历史筹码，等有空座再上场；新玩家使用房间设置的初始筹码，后续补充计入该玩家投入。
4. 主动离场立即按弃牌处理，已投入筹码保留在底池；同房间回来保留该人的持有筹码及累计投入，本小局不得重新行动，下一小局有空位后再上场。仅临时断线不弃牌；房主在离线较久提示后可确认其已离开，再执行弃牌。
5. 使用每房间每设备的本地临时身份来恢复座位与余额，IP 和端口仅作传输地址。新房间生成新身份；名称不是身份。正式协议不记录或展示密码、身份凭据及密钥到诊断日志；房间密码属于加入控制，不能声称已实现传输加密或强身份认证。
6. 房主短暂中断时数据保留：能确认的操作才成功，无法确认时等待重连；离线较久时所有玩家看到等待房主。房主主动解散后，其他设备提示已解散、保留最后确认画面并锁定修改类按钮，允许自行离开。
7. 房主意外退出 App 后，在创建房间时提示恢复未主动解散的最近房间，显示房间名和最后保存年月日时分。恢复使用原房间身份及确认状态，其他设备在前台自动重试并完整同步；创建新房间不沿用旧对局。主动解散的房间不可恢复为活动房间。
8. 查看盈亏只是预览：本地菜单可打开；联机每名玩家可独立查看最近确认快照，离线时标记可能过期。当前未分配底池按各自投入临时计回，不改变牌局。逐人计算 `(当前持有 + 本小局投入 - 本场累计领入筹码) × 单价`，包括离场者，提供个人对个人转账建议，不设组合。新本地牌桌、明确重置和新房间分别从新的投入账本开始。

## 关键风险与验收用例

- 先后参与者总数超过 9，离场者和重入者仍按稳定 ID 唯一记账；满座时回归玩家只能等待。
- 未轮到的玩家离场、大小盲离场、全下玩家离场、剩一人、主池边池和当前行动者离场时，下注轮次及筹码守恒。
- 用户操作报文及确认报文分别丢失、重复或乱序：同一操作最多生效一次，旧快照不覆盖新快照；丢失最后一次广播后心跳发现版本差并重取。
- 房主已保存但确认丢失时重启：操作与去重记录一起恢复，不重复扣筹码；保存失败时不能确认成功，界面明确失败。
- 暂存操作与远端版本冲突、超时、房主解散报文丢失、重连时 IP 或端口变化、恢复后有旧包到达：均不得静默修改新房间状态。
- 单价小数、超过两位小数、金额精度和超过安全整数范围、平局余数、离场余额及非零底池预览：不得产生不平衡或伪造的转账建议。
