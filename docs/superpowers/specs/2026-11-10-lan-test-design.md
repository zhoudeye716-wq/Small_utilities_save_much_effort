# 局域网联机测试设计

## 目标和范围

在现有小程序首页增加独立的「局域网联机测试」入口。多台安卓手机、iPhone 或 iPad 在同一 Wi‑Fi 或手机热点下，测试建房、搜索、手动加入、消息同步、时延、丢包、吞吐以及断线恢复。房间由一台设备托管，不部署云服务器。

测试功能使用独立页面、存档键和网络逻辑。首页增加入口并注册页面，六个已有工具保持各自的逻辑和存档。设备需能打开同一个开发版或体验版小程序。

## 使用流程

1. 首页进入测试板块，显示设备系统、微信和基础库版本、Wi‑Fi 状态，以及「创建房间」「搜索房间」和「手动加入」。
2. 房主创建带临时房间编号的房间，显示名称、加入地址和端口。其他设备搜索并选择房间，也可填写房主显示的局域网 IP 与端口直接加入。
3. 房主和成员看到成员列表与在线状态。房主选择一个成员进行双向测试。可同时加入多个成员，统计按成员和方向分开显示。
4. 房间里支持发一条测试消息、往返延迟测试、连续消息测试和吞吐测试。每次测量显示进行中、完成、中断或失败，以及样本量。
5. 手动关闭 Wi‑Fi、切后台或让房主离开，观察断线和恢复。若未收到确认，显示「等待回复」或「超时」，保留接口错误，避免直接判断为某种网络故障。
6. 页面内可看本机实时日志、最近一次测试报告和成员回报。可一键复制当前设备的报告及日志，发送给开发者分析。

## 搜索和加入

- 使用 `wx.createUDPSocket`，房主绑定一个大于 1024 的测试端口。搜索者向本网络广播搜索请求，房主向请求来源单播房间信息；房间列表以房间 ID 去重并标记过期。
- 自动搜索和手动加入共用加入握手。握手包含测试协议版本、房间 ID、设备临时 ID 和一次性请求编号。房主确认后才标记「已加入」，重复握手保持幂等。
- 广播、单播、绑定和获取 IP 分别记录开始、成功、错误或超时。自动搜索失败后可直接尝试手动加入。房主无法自动获取 IP 时显示原因，允许从设备网络设置手工查询。
- 不用 mDNS 作为唯一发现方式。iOS 对局域网访问和广播可能有系统及微信宿主限制，实际支持情况按真机结果记录。

## 测量规则

- **单条消息**：为每条消息分配序号，显示发送、接收和回复状态。消息内容为用户输入的短文本，输入不包含账号资料。
- **延迟**：默认每秒一个请求，共 30 个。发送端用同一设备的计时器记录发送到收到回复的往返时间。报告发送数、回复数、超时数，以及有效样本的平均、中位数、95 分位和最大值。无有效回复时显示「无法计算」。
- **连续消息**：默认每秒 10 条，共 100 条，每条带测试 ID 与序号。接收端统计实际收包、去重后的序号、重复及乱序，并回报序号集合。发送端显示原始送达和超时；需重发的可靠传递作为单独结果，避免掩盖原始丢包。
- **吞吐**：默认每次测一个方向，再可切换方向。采用固定时长、受限速率的短包流，初始包体总长约 1024 字节。接收方按独立序号累计有效载荷，报告实际接收字节及接收速度 KiB/s，并注明运行时长、有效包数和协议开销是否计入。
- 微信类型定义规定 UDP 接收消息长度小于 4096 字节。所有包先按实际编码后的完整报文长度校验并留足余量。无需双机时钟同步，不推算单向延迟。
- 测试 ID、序号、超时、去重及最终报告要能处理乱序、丢包、重复和对端中断。无法拿到接收端统计时显示「报告未收到」，不把该次速度标为零或成功。

## 日志与结果

- 页面实时展示可筛选的阶段和日志。关键记录包括时间、相对测试时间、设备角色、房间 ID、测试 ID、事件、目标地址和端口、成功或错误，以及测试统计。
- 同一测试的两端使用相同测试 ID，便于对照。接收端报告可展示在房主界面；对端报告未到达时，双方分别保留自己的日志。
- 最近一次测试结果与必要日志单独保存本机，关闭小程序后可查看。开始新一轮测试时替换上一轮。记录数量有上限，达到上限时保留关键错误和汇总，并明确提示日志截断。
- 报告一键复制，复制前显示包含局域网 IP、端口、设备及微信版本。复制由用户触发，不自动上传或发送。日志不采集微信账号、聊天内容或其他六个工具的数据。

## 真机验证

分别让安卓、iPhone/iPad 担任房主与成员，覆盖安卓↔安卓、安卓↔iPhone/iPad、iPhone/iPad↔iPhone/iPad。每组记录机型、系统版本、微信版本、基础库、Wi‑Fi 或热点类型、自动发现及手动加入结果。

同时检查多人加入、原始丢包与顺序、断网恢复、房主切后台或退出。若微信或系统不允许某项操作，保留具体现象和错误，不以模拟器结果代替真机结论。
